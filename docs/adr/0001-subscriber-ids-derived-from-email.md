# Subscriber document ids are derived from the email

A Subscriber's Sanity `_id` is `subscriber.<sha256 of the normalised email>`, not a random id. Saving is then a `createOrReplace` on a known id, so two simultaneous sign-ups for the same address can't create duplicate Subscribers (with random ids, subscribe's read-then-create races). The `.` in the id also matters: the dataset is public so the blog can be read without a token, and Sanity only serves documents whose id contains a `.` to authenticated requests, which keeps Subscriber emails out of the public API. There were no Subscribers when this was adopted, so nothing was migrated. Changing the normalisation or id format (e.g. stripping `+tags`) changes every id and needs a migration.
